# pstack-devin Marketplace Registration + Distribution Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register `pstack-devin` in the repo's APM marketplace and verify both real distribution paths — `apm install` (primitives) and `devin plugins install` (the generated plugin) — without disturbing existing lockstep packages.

**Architecture:** Registration-only changes to root `apm.yml` + `apm install`-regenerated lockfiles; verification is real (public repo, `devin` CLI on the maintainer machine) — GitHub `#subdir` install and `--local` install both exercised, results recorded in `docs/distribution-verification.md`. A new `check:marketplace` test pins the registration invariants so drift (missing entry, lockfile stale, wrong subdir) fails loudly.

**Tech Stack:** existing `scripts/pstack-devin` harness + `apm`/`devin` CLIs via `mise exec --`.

## Global Constraints

- Root `apm.yml` edits are LIMITED to: `devDependencies.apm` += `./packages/pstack-devin`, `marketplace.packages` += one entry `{name: pstack-devin, category: workflow, source: scarecrow173/apm-packages, subdir: packages/pstack-devin}`. No other root-file changes; existing entries/lockstep untouched.
- Lockfiles regenerated ONLY via `apm install` — never hand-edited. Root `apm.lock.yaml` gains the `local_path: ./packages/pstack-devin` entry; package `apm.lock.yaml` unchanged (regenerate only if it drifts).
- NO dependencies added to `recommended-dev-suite`/`doc-driven-dev-graph` (issue non-goal).
- `devin-plugin/` is a checked-in build artifact — `.gitignore`/`worktreeinclude` audited so caches stay ignored while the artifact stays tracked.

## Verified Facts

- Repo is PUBLIC → `devin plugins install scarecrow173/apm-packages#packages/pstack-devin/devin-plugin` works against main.
- Root marketplace entry shape (from existing): `{name, category, source: scarecrow173/apm-packages, subdir: packages/<name>}`; `versioning.strategy: lockstep`.
- `apm install` on a `path:` dep deploys `.apm` primitives only (3 files: setup-pstack-devin skill) — it does NOT install `devin-plugin/`; that separation must be documented.
- `devin plugins list`/`install`/`info` verified on devin 3000.12.57; plugins land under `%APPDATA%\devin\cli\plugins\` (Windows).
- `plugin.json` already ships `name: pstack`, `platforms: ["local"]` — verified by `l3-dist`.
- Name collision: upstream `cursor/plugins#harness/pstack/claude-code` also claims `pstack` — install only one; documented in decisions §4.
