# pstack-devin APM Feasibility & Package Definition Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify with real commands that `packages/pstack-devin` can pin upstream `cursor/plugins` `harness/pstack/claude-code` under APM 0.33.0, record the verified constraints, and land the package skeleton plus a single-authority upstream pin and an evidence-backed design record — issue `#212`.

**Architecture:** Empirical verification first (scratch consumers + the package's own `devDependencies` pin), then skeleton files, then an ADR-lite decision record. The upstream tree is an `agent_plugin` package that APM deploys only for `copilot` and records `deployments: []`, so distribution is via a build-side snapshot at a pinned commit (`scripts/pstack-devin`, issue `#213`); the APM `devDependencies` entry exists solely for lockfile attestation (`resolved_commit` + `content_hash`).

**Tech Stack:** APM 0.33.0 (mise), Node 24 + pnpm 11 + tsx + node:test (per `scripts/<pkg>` convention), js-yaml, markdownlint-cli2, `gh` CLI, git-bash.

## Global Constraints

- APM is pinned by `mise.toml` as `"github:microsoft/apm" = "0.33.0"`. Inside the repo always run `mise exec -- <cmd>`. In scratch dirs **outside** the repo, `mise exec` cannot resolve tools — resolve once with `APM="$(cd /g/repositry/apm-packages && mise which apm)"` and call `"$APM"`.
- Upstream pin (verified 2026-11-16): repo `cursor/plugins`, path `harness/pstack/claude-code`, commit `bf0c7cd80abdbf7fe47b634978a7d1b4071f71a7`, upstream `plugin.json` version `0.15.42`, license MIT, 546 blob files.
- Upstream files ship byte-identical except an explicit overwrite allowlist; the only allowlist candidate so far is `skills/setup-pstack/SKILL.md`.
- The upstream tree must never appear in `dependencies:` — it is an `agent_plugin` that resolves for `copilot` only and would break every other consumer target. It may appear only in `devDependencies:` with `targets: [copilot]`.
- `upstream.yml` is the single authority for upstream coordinates. `upstream.upstream.commit`, the devDep `ref`, and `apm.lock.yaml`'s `resolved_commit` must be equal at all times.
- `apm.lock.yaml` is generated by `apm install` only — never hand-edited. Install side-effects (`apm_modules/`, `.github/`, `.claude-plugin/`, `build/`) stay gitignored.
- Do **not** touch root `apm.yml`, root `apm.lock.yaml`, or the marketplace block — registration belongs to issue `#217`.
- `README.md`/`README.ja.md` and `AGENTS.md`/`AGENTS.ja.md` must stay synchronized in structure and meaning. `docs/` maintainer records may stay English-only.
- In commit messages and docs, do not write references that auto-link to repositories we do not own (e.g. `cursor/plugins#123`); `#<n>` refers to this repository's issues only.
- Verification policy (from issue `#212`): never adopt an unverified YAML schema or doc-only claim as spec. Every `Expected:` output below was actually observed under APM 0.33.0 on 2026-11-16; if a re-run diverges, record the **actual** output and flag it in the decision record instead of editing expectations silently.

`scripts/pstack-devin/tests/package-structure.test.ts`:

```ts
import assert from "node:assert/strict";
import fs from "node:fs";
import path from "node:path";
import { load } from "js-yaml";
import test from "node:test";

const repoRoot = path.resolve(__dirname, "../../..");
const pkgRoot = path.join(repoRoot, "packages", "pstack-devin");

const upstream = load(
  fs.readFileSync(path.join(pkgRoot, "upstream.yml"), "utf8"),
) as { upstream: { repo: string; path: string; commit: string } };

const manifest = load(
  fs.readFileSync(path.join(pkgRoot, "apm.yml"), "utf8"),
) as Record<string, unknown>;

const COMMIT_RE = /^[0-9a-f]{40}$/;

test("required package files exist", () => {
  for (const rel of [
    "apm.yml",
    "upstream.yml",
    "README.md",
    "README.ja.md",
    "AGENTS.md",
    "AGENTS.ja.md",
    ".gitignore",
    ".markdownlint-cli2.jsonc",
    ".apm/.gitkeep",
    "docs/verification-apm-0.33.0.md",
    "apm.lock.yaml",
  ]) {
    assert.ok(fs.existsSync(path.join(pkgRoot, rel)), `missing: ${rel}`);
  }
});

test("upstream.yml pins a full 40-hex commit for cursor/plugins", () => {
  assert.equal(upstream.upstream.repo, "cursor/plugins");
  assert.equal(upstream.upstream.path, "harness/pstack/claude-code");
  assert.match(upstream.upstream.commit, COMMIT_RE);
});

test("manifest carries the upstream pin only as a copilot-scoped devDependency", () => {
  assert.equal(manifest.name, "pstack-devin");
  assert.ok(
    !("dependencies" in manifest),
    "upstream tree must not ship via `dependencies:`",
  );
  const dev = (manifest.devDependencies as { apm: unknown[] }).apm;
  assert.equal(dev.length, 1);
  const dep = dev[0] as Record<string, unknown>;
  assert.equal(dep.git, "https://github.com/cursor/plugins.git");
  assert.equal(dep.path, "harness/pstack/claude-code");
  assert.equal(dep.ref, upstream.upstream.commit);
  assert.deepEqual(dep.targets, ["copilot"]);
  assert.ok(
    (manifest.targets as string[]).includes("copilot"),
    "manifest targets must include copilot for the devDep pin to resolve",
  );
});

test("lockfile attests the same commit as upstream.yml", () => {
  const lock = load(
    fs.readFileSync(path.join(pkgRoot, "apm.lock.yaml"), "utf8"),
  ) as {
    dependencies: Array<Record<string, unknown>>;
    deployments?: unknown[];
  };
  assert.equal(lock.dependencies.length, 1);
  const entry = lock.dependencies[0];
  assert.equal(entry.resolved_commit, upstream.upstream.commit);
  assert.equal(entry.is_dev, true);
  assert.equal(entry.package_type, "agent_plugin");
  assert.deepEqual(entry.target_subset, ["copilot"]);
  assert.ok(
    typeof entry.content_hash === "string" &&
      entry.content_hash.startsWith("sha256:"),
    "lockfile must attest content_hash",
  );
  assert.deepEqual(
    lock.deployments ?? [],
    [],
    "APM attests no per-file deployments; the tree must be built, not installed",
  );
});
```

# pstack-devin

Devin CLI compatible distribution of the upstream
[pstack](https://github.com/cursor/plugins) workflow pack
(`harness/pstack/claude-code`), pinned to a fixed upstream commit.

> Status: early scaffolding. The deterministic builder and the Devin plugin
> output are not implemented yet; see the issue chain under

## Artifacts and boundaries

This directory hosts two related but distinct artifacts:

| Artifact | Location | Consumed by | Contents |
| --- | --- | --- | --- |
| APM package | `packages/pstack-devin/` | `apm install` consumers | Adapter/setup primitives under `.apm/` (added in later issues) |
| Devin plugin | `packages/pstack-devin/devin-plugin/` | `devin plugins install` | Byte-pinned upstream pstack tree plus a thin Devin overlay (generated by `scripts/pstack-devin`; not yet present) |

primitives. It does **not** imply Devin CLI support: Devin consumes the built

and commit. `apm.yml` carries the same pin as a `devDependencies` entry so
that `apm.lock.yaml` attests `resolved_commit` and `content_hash`; the three
values must always agree. A mismatch is a hard failure, not a warning.

Upstream files ship byte-identical except for an explicit overwrite
allowlist. See `docs/upstream-source-decision.md` for the verified
rationale and `docs/verification-apm-0.33.0.md` for the reproduction log.

## Layout

  upstream.yml       # pinned upstream coordinates (single authority)
  apm.lock.yaml      # generated by `apm install`; committed as attestation
  docs/              # verification log and design record (maintainer-facing)
  devin-plugin/      # generated Devin plugin output (not yet present)
  .apm/              # APM primitives (added by later issues)
```

## Install

Not published yet. The APM and Devin install paths, including known
limitations, are verified and documented in later issues of the chain.

# AGENTS.md

Guide for agents maintaining `packages/pstack-devin`.

## Package role

`pstack-devin` distributes the upstream `cursor/plugins`
`harness/pstack/claude-code` tree to Devin CLI without forking it. Treat
[apm.yml](./apm.yml) and [upstream.yml](./upstream.yml) as the contract
surface; `docs/` holds maintainer-facing evidence, not user docs.

## Artifact boundary

- `.apm/` primitives (added by later issues) serve APM consumers.
- `devin-plugin/` is a generated, git-tracked Devin plugin produced by
  `scripts/pstack-devin`. Never edit it by hand; regenerate via the build.
- `targets:` in `apm.yml` covers APM runtimes only. It must keep `copilot`
  listed: the provenance `devDependencies` entry is an `agent_plugin`
  package that resolves only when `copilot` is an active target. Listing
  `copilot` does not imply Copilot workflow support beyond that pin, and it
  never implies Devin support.

## Upstream pin rules

- `upstream.yml.upstream.commit` is the single authority for the upstream
  snapshot. The `devDependencies.apm[0].ref` in `apm.yml` and
  `apm.lock.yaml`'s `resolved_commit` must equal it at all times.
- Regenerate `apm.lock.yaml` only by running `apm install` inside this
  directory. Never hand-edit it.
- `apm_modules/`, `.github/`, `.claude-plugin/`, and `build/` are local
  install/pack side-effects and stay gitignored.
- Upstream files are byte-identical except the overwrite allowlist
  (currently only `skills/setup-pstack/SKILL.md`; see
  `docs/upstream-source-decision.md`).

## Editing rules

- Keep `README.md`/`README.ja.md` and `AGENTS.md`/`AGENTS.ja.md`
  synchronized in structure and meaning.
- Do not add the upstream tree to `dependencies:`; consumers would inherit
  a copilot-only `agent_plugin` resolution and fail on other targets.
- Do not edit the root `apm.yml`, `apm.lock.yaml`, or marketplace block;
  registration is handled in the marketplace issue (`#217`).
- `docs/` files are maintainer-facing and may stay English-only; README and

  that line is expected.

# Decision: upstream pstack source of truth and distribution path

Status: accepted (verified against APM 0.33.0 — see `verification-apm-0.33.0.md`)
Date: 2026-11-16 · Issue: `#212`

## Context

`harness/pstack/claude-code` in `cursor/plugins` @`bf0c7cd8` is 546 files and
is classified by APM 0.33.0 as `package_type: agent_plugin` (Agent Plugins
v1.0.0, from `plugin.json` / `.claude-plugin/plugin.json`).

## Verified facts driving the decision

1. A virtual-subdirectory dependency resolves and pins correctly
   (`resolved_commit` = pinned SHA; `content_hash` attested).
2. `agent_plugin` packages install natively only for the `copilot` target;
   any other selected target fails the whole install transaction.
3. Under `copilot`, APM deploys zero tree files. It registers the plugin
   with Copilot's native mechanism (`.github/copilot/settings.local.json`:
   `enabledPlugins: pstack@apm`, `extraKnownMarketplaces` -> `apm_modules`).
   The lockfile records `deployments: []`.
4. `apm pack` bundles exclusively lockfile-attested `deployed_files`; with
   `deployments: []` an APM dependency can never ship the upstream tree.
5. Declaring the dependency under `dependencies:` would push the same
   copilot-only resolution onto every consumer and fail non-copilot
   installs outright.

## Decision

- The upstream tree is fetched build-side at a pinned commit by
  `scripts/pstack-devin` (issue `#213`), not delivered through an APM
  dependency. `upstream.yml` is the single authority for repo/path/commit.
- `apm.yml` carries the pin only as a `devDependencies` entry scoped
  `targets: [copilot]`: it produces `apm.lock.yaml` attestation
  (`resolved_commit`, `content_hash`, `is_dev`) with no consumer impact —
  devDeps are not installed transitively and are excluded from `apm pack`
  bundle contents.
- The upstream dep MUST NOT appear in `dependencies:`.
- Mismatch contract: `upstream.yml.upstream.commit`, the devDep `ref`, and
  `apm.lock.yaml.dependencies[0].resolved_commit` must be equal; the
  builder (issue `#213`) hard-fails on divergence and reports which side
  moved.
- `devin-plugin/` output is git-tracked under this package (generated by
  `#213`; published by `#217`).

## Alternatives rejected

- APM `dependencies:` on the virtual subdir — copilot-only `agent_plugin`,
  zero file deployment, breaks non-copilot consumer installs.
- Per-skill deps (`.../claude-code/skills/<name>`) — ships only skill-bundle
  primitives and loses playbooks, scripts, docs, images, and LICENSE
  (546 files reduced to a subset); also invents a second authority for what
  ships.
- Floating `#main` ref — violates the pinned-upstream rule.

## Consequences

- `scripts/pstack-devin` owns fetching (sparse checkout or equivalent at
  the pinned SHA), overlay, provenance, and determinism (issue `#213`).
- `apm.lock.yaml` here is generated by `apm install` only — never
  hand-edited.
- An upstream bump is one coordinated change: `upstream.yml` commit +
  `apm.yml` devDep `ref` + regenerate `apm.lock.yaml` + rebuild
  `devin-plugin/` (automation: issue `#219`).
- `apm audit` <does/does not — per verification §3d> detect cache tampering;
  the rebuild-time recompute is the authoritative integrity gate regardless.
```
