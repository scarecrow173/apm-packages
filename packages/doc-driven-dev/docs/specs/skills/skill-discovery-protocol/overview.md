## Purpose

`skill-discovery-protocol` is a protocol that scans externally installed
standard `SKILL.md` skills, supplements capability information through agent
inference, and produces a flow-neutral catalog plus flow-specific profiles.

`SKILL.md` files are not required to carry `provides` / `uses` / `tags` /
`execution_policy` beyond standard metadata. Scan stores the full text of each
discovered `SKILL.md` in `skill-scan-list.json`; an agent reads that text and
produces `skill-reference-inferences.json`. The catalog is generated by joining
the scan artifact with the inference artifact.
`runtime_guidance` is a soft ranking signal used when a flow selects
candidates, and is treated separately from `execution_policy`.

## Scope

### In Scope

- Loading adapter YAML and resolving `extends`
- Skill scan across project/user/organization/builtin scopes
- Generating `skill-scan-list.json` from scan results
- Validating the agent-inference artifact `skill-reference-inferences.json`
- Generating the Skill Reference Catalog
- Flow-specific classification
- Invocation resolution
- Generating the Flow Profile
- Generating the validation report
- Generating readable Markdown sidecars
- `sdp scan` / `sdp infer` / `sdp profile` / `sdp validate` / `sdp query` CLI

### Out of Scope for MVP

- Executing runtime skill activation
- Remote skill installation
- Running automatic inference via an LLM API itself
- Priority-based conflict resolution across multiple adapters

## Design Principles

- **Flow-neutral**: the catalog holds no flow-specific slots or classification
  results
- **Standard SKILL.md assumed**: no custom fields are required in `SKILL.md`
- **Scan/inference separation**: scan collects full text, inference reasons
  about capabilities, catalog normalizes
- **Adapter isolation**: flow-specific logic is confined to adapter YAML
- **Script-only**: artifacts are generated, updated, and validated through
  scripts
- **Machine-readable first**: JSON is the canonical artifact; Markdown is a
  derivative

## Artifact Model

```text
skill-scan-list.json
  - name / description / body / skill_path / scope of each SKILL.md found by scan
  - input for agent inference

skill-reference-inferences.json
  - review_status / provides / uses / execution_policy / runtime_guidance / tags
    inferred by the agent from the full SKILL.md text
  - input for catalog construction

skill-reference-catalog.json
  - flow-neutral capability catalog joining scan and inference
  - holds no invocation slots or classification results

*-profile.json
  - flow-specific artifact based on an adapter
  - holds flow_stack.slots[] / resolved_invocations / runtime_guidance

validation-report.json
  - validation results for schema / staleness / deterministic / blocking
```

## Public Workflow and Internal Steps

The public workflow splits into `sdp scan`, agent inference, `sdp infer`, and
`sdp profile`. `sdp profile` reads the scan/inference artifacts but does not
generate them implicitly.

The canonical internal steps are:

```text
load_adapter -> scan_skills -> write_scan_list
-> read_skill_reference_inferences -> build_skill_reference_catalog
-> classify_skills -> resolve_invocations -> build_flow_profile
-> render_outputs -> validate_outputs
```

| Step | Input | Output |
| --- | --- | --- |
| `load_adapter` | adapter YAML | merged config |
| `scan_skills` | scopes + roots | raw skill list |
| `write_scan_list` | raw skill list | `skill-scan-list.json` |
| `read_skill_reference_inferences` | `skill-reference-inferences.json` | inferred skill capabilities |
| `build_skill_reference_catalog` | scan list + inferences | Skill Reference Catalog JSON |
| `classify_skills` | catalog + taxonomy | classified skills |
| `resolve_invocations` | classified + overrides | resolved_invocations |
| `build_flow_profile` | all above | Flow Profile JSON |
| `render_outputs` | JSON artifacts | stable-sorted JSON + optional MD |
| `validate_outputs` | artifacts | Validation Report |

## Command Surface

| Command | Responsibility |
| --- | --- |
| `sdp scan --adapter <yaml>` | Generate the scan list |
| `sdp infer init [--scan <json>] [--out <json>]` | Initialize/update the inference artifact |
| `sdp infer check [--scan <json>] --in <json>` | Validate inference schema/completeness |
| `sdp profile --adapter <yaml>` | Generate catalog/profile from existing scan + inference artifacts |
| `sdp validate --profile <json>` | Validate artifacts |
| `sdp query --profile <json> <subcommand>` | Extract information from artifacts |

| Artifact | Format | Role |
