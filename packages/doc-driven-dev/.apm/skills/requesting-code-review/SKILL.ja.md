# コードレビュー依頼（Requesting Code Review）

問題がカスケードする前にキャッチするため、コードレビューサブエージェントをディスパッチする。レビュアーには評価用の精密に構築されたコンテキストを渡す — セッション履歴は渡さない。

**核心原則:** 早期にレビュー、頻繁にレビュー。

## レビュー依頼のタイミング

**必須:**
- subagent-driven-development の各タスク後
- 主要機能完了後
- main へのマージ前

**任意だが価値あり:**
- 行き詰まった時（フレッシュな視点）
- リファクタリング前（ベースラインチェック）
- 複雑なバグ修正後

## 依頼方法

1. git SHA を取得
2. `assets/templates/code-reviewer.md` テンプレートを使ってレビューサブエージェントをディスパッチ
3. フィードバックに対応:
   - Critical 問題は即座に修正
   - Important 問題は進行前に修正
   - Minor 問題はメモして後で対応
   - レビュアーが間違っていれば技術的根拠で反論

## レッドフラグ

- 「シンプルだから」でレビューをスキップ
- Critical 問題を無視
- 未修正の Important 問題で先に進む
- 正当な技術的フィードバックに反論
