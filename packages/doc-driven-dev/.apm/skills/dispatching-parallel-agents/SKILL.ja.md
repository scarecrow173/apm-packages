# 並行エージェントディスパッチ（Dispatching Parallel Agents）

## 概要

タスクを分離されたコンテキストを持つ専門エージェントに委任する。指示とコンテキストを精密に構築することで、エージェントが集中してタスクを成功させることを保証する。セッションのコンテキストや履歴を継承させない — 必要なものだけを構築する。

**核心原則:** 独立した問題ドメインごとに 1 エージェントをディスパッチ。並行実行させる。

## 使用タイミング

**使用する場合:**
- 異なる根本原因で 3 つ以上のテストファイルが失敗している
- 複数のサブシステムが独立して壊れている
- 各問題が他のコンテキストなしに理解できる
- 調査間に共有状態がない

**使用しない場合:**
- 失敗が関連している（一つ修正すれば他も直る可能性）
- システム全体の状態理解が必要
- エージェント同士が干渉する（同じファイルを編集）
- 探索的デバッグ（何が壊れているか不明）

## パターン

### 1. 独立したドメインを特定

### 2. 集中したエージェントタスクを作成

各エージェントに:
- **具体的スコープ:** 一つのテストファイルまたはサブシステム
- **明確なゴール:** これらのテストを通す
- **制約:** 他のコードを変更しない
- **期待出力:** 発見と修正の要約

### 3. 並行ディスパッチ

### 4. レビューと統合

エージェントが返ったら:
- 各要約を読む
- 修正が衝突しないか確認
- フルテストスイートを実行
- 全変更を統合

## 良いプロンプトの条件

1. **集中** — 一つの明確な問題ドメイン
2. **自己完結** — 問題を理解するために必要な全コンテキスト
3. **出力が具体的** — エージェントが何を返すべきか

## 検証

1. 各要約をレビュー
2. 衝突チェック
3. フルスイート実行
4. スポットチェック（エージェントは系統的エラーを起こしうる）
