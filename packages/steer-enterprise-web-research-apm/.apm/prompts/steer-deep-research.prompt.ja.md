SteER / Enterprise Deep Research 型の調査を実行してください。

調査テーマ:
${input:topic:何を調査しますか？}

判断 / ユースケース:
${input:decision:この調査はどのような意思決定を支援するものですか？}

出力形式:
${input:format:レポート、比較表、実装計画、ベストプラクティスガイド、その他のどれですか？}

制約:
${input:constraints:対象期間、地域、情報源の好み、除外条件、深さ、読者などはありますか？}

プロセス要件:

1. 次を作成または内部的に維持する。
   - todo 計画
   - ペルソナ / 意図モデル
   - クエリログ
   - 証拠台帳
   - running summary
   - 監査メモ

2. 反復的に検索する。
   - 該当する場合は公式 / 一次情報源を最初に使う。
   - 一般 Web
   - 研究志向の場合は学術情報源
   - 実装志向の場合は GitHub / ソースリポジトリ
   - 制限や矛盾を検出するための批判的 / 否定的クエリ

3. 各ループ後に監査する。
   - 網羅性
   - 情報源品質
   - 鮮度
   - 矛盾
   - 未解決ギャップ
   - 追加の対象検索が必要かどうか

4. 大きな分岐、曖昧さ、矛盾、または高コストな探索分岐が結果に大きく影響する場合だけ、ユーザーにステアリング確認する。

5. 最終回答には次を含める。
   - スコープと前提
   - 主要な発見
   - 根拠付き分析
   - 信頼度ラベル
   - 未解決ギャップ
   - 推奨される次のアクション
   - 確認した情報源に基づく引用またはソースリスト

引用や事実を捏造してはならない。検索ツールが利用できない場合は、その旨を述べて調査計画だけを作る。
