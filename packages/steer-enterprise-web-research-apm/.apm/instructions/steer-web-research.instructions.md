# SteER Web Research Repository Instructions

Use this workflow when the user asks for web research, current information, tool/paper/framework discovery, evidence-backed reports, multi-round investigation, source quality comparison, research audit, re-search, or GitHub/open-source implementation discovery.

## Core workflow

- Clarify only high-impact ambiguity.
- Build a lightweight intent/persona model.
- Create a todo-driven research plan.
- Generate diverse search directions.
- Decide whether to pause using cost-benefit judgment.
- Search and record evidence.
- Deduplicate and rate source reliability.
- Reflect on gaps, contradictions, freshness, and coverage.
- Repeat targeted searches until sufficiency criteria are met.
- Produce a cited report with confidence levels and unresolved gaps.

## State files

When writing files, use:

- `research/todo.md`
- `research/persona.md`
- `research/query-log.md`
- `research/evidence-ledger.md`
- `research/running-summary.md`
- `research/audit.md`
- `research/final-report.md`

## Quality bar

- Prefer primary sources.
- Do not use stale facts for current claims.
- Do not cite sources that were not inspected.
- Do not hide contradictions.
- Do not invent missing facts.
- Disclose uncertainty.
- For technical tools, inspect official docs, changelogs, source repositories, releases, and issues where possible.
- For papers, inspect the paper page and PDF or abstract, not only a blog summary.
