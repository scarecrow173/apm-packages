# AGENTS.md

Guide for agents maintaining `packages/pstack-devin`.

## Package role

`pstack-devin` distributes the upstream `cursor/plugins`
`harness/pstack/claude-code` tree to Devin CLI without forking it. Treat
[apm.yml](./apm.yml) and [upstream.yml](./upstream.yml) as the contract
surface; `docs/` holds maintainer-facing evidence, not user docs.

## Artifact boundary

- `.apm/` primitives (currently `skills/setup-pstack-devin/`, added in
  `#215`) serve APM consumers.
- `devin-plugin/` is a generated, git-tracked Devin plugin produced by
  `scripts/pstack-devin`. Never edit it by hand; regenerate via the build.
- `targets:` in `apm.yml` covers APM runtimes only. It must keep `copilot`
  listed: the provenance `devDependencies` entry is an `agent_plugin`
  package that resolves only when `copilot` is an active target. Listing
  `copilot` does not imply Copilot workflow support beyond that pin, and it
  never implies Devin support.

## Upstream pin rules

- `upstream.yml.upstream.commit` is the single authority for the upstream
  snapshot. The `devDependencies.apm[0].ref` in `apm.yml` and
  `apm.lock.yaml`'s `resolved_commit` must equal it at all times.
- Move the pin only via `pnpm --dir scripts/pstack-devin run apply:update
  <sha>` (atomically: refs + `apm install` lockfile + rebuilt tree +
  verify + one commit) or the weekly upstream-watch workflow — see
  `docs/upstream-updates.md`. Never bump a pin file without the rest.
- Regenerate `apm.lock.yaml` only by running `apm install` inside this
  directory. Never hand-edit it.
- `apm_modules/`, `.github/`, `.claude-plugin/`, and `build/` are local
  install/pack side-effects and stay gitignored.
- Upstream files are byte-identical except the overwrite allowlist
  (`skills/setup-pstack/SKILL.md` overwritten as the Devin delegation
  entry in `#215`; `agents/poteto-agent.md` overwritten as a
  Devin-native profile in `#214`; see `docs/upstream-source-decision.md`
  and `docs/devin-adapter-decisions.md`).

## Generated `devin-plugin/` rules

- Regenerate `devin-plugin/` only via
  `pnpm --dir scripts/pstack-devin run build` from the repository root.
  `devin-plugin/` is generated output — never edit it by hand.
- `overlay/` holds authored overlay source; `overlay.yml` is the single
  overwrite authority. An overlay path may replace an upstream file only
  when listed under `allow_overwrite:`; every other overlay path must be
  an addition. Widening the allowlist is a policy change, not a drive-by.
- `provenance.json` carries no timestamps by design — identical inputs
  must produce byte-identical output. Do not add time-varying fields.
- Executable bits are staged via `git update-index --chmod=+x` (the build
  and `check` do this themselves) because the repo is committed on
  Windows with `core.fileMode=false`. The index mode set must equal
  `provenance.executables`.
- Keep `.markdownlint-cli2.jsonc` `ignores` covering `devin-plugin/**`:
  generated bytes are not authored documentation.
- Evidence for the current committed tree is recorded in
  `docs/build-verification.md`; refresh it when the pin or overlay
  contract changes.

## Editing rules

- Keep `README.md`/`README.ja.md` and `AGENTS.md`/`AGENTS.ja.md`
  synchronized in structure and meaning.
- Do not add the upstream tree to `dependencies:`; consumers would inherit
  a copilot-only `agent_plugin` resolution and fail on other targets.
- Do not edit the root `apm.yml`, `apm.lock.yaml`, or marketplace block;
  registration is handled in the marketplace issue (`#217`).
- `docs/` files are maintainer-facing and may stay English-only; README and
  AGENTS must remain bilingual. `docs/migration.md` is the exception: it is
  user-facing and bilingual — keep `migration.ja.md` in sync.
- `apm install` may append `apm_modules/` to this directory's `.gitignore`;
  that line is expected.

## Runtime behavior (session start)

- Plugin skills, `pstack:*` agent profiles, and `~/.devin/rules/` rules
  load at session start: an install or a `/pstack:setup-pstack` run
  applies to new sessions. Every recorded probe ran in a session begun
  after the `--local` install; whether a running session picks up an
  install is not verified.
- pstack is opt-in: the plugin's always-on `AGENTS.md` only maps adapter
  docs — nothing activates until a `/pstack:<skill>` invocation. Proven
  by the non-interference control (`docs/runtime-verification.md`
  §3.7): a plain prompt with the plugin installed produced a plain
  answer and zero `pstack` activity.
- Evidence map: real-CLI probes and verdicts in
  `docs/runtime-verification.md` (its `## 5. Compatibility` is the
  support matrix); deterministic checks in
  `docs/verification-matrix.md`; consumer switching guidance in
  `docs/migration.md`.

## Validation

From this directory:

```bash
mise exec -- apm install --frozen   # lockfile/manifest must be in sync
mise exec -- apm compile --dry-run  # consumer-context preview only
```

`apm compile --validate` counts instruction/agent primitives only; this
package ships a skill (`.apm/skills/setup-pstack-devin/`), so the command
reports "No instruction files found" and exits non-zero — the same result
the repo's other skills-only packages get. With `apm_modules/` installed
the exit-0 form of the same N/A appears instead: "Validated 0 primitives"
with zero of every instruction-shaped kind. Report either outcome as not
applicable instead of treating it as a package bug.

From the repository root:

```bash
mise exec -- pnpm --dir scripts/pstack-devin test
mise exec -- pnpm --dir scripts/pstack-devin run lint:md
mise exec -- pnpm --dir scripts/pstack-devin run check-generated
mise exec -- pnpm --dir scripts/pstack-devin run audit:compat
```
