# サブエージェント駆動開発（Subagent-Driven Development）

タスクごとにフレッシュなサブエージェントをディスパッチし、各タスク後に2段階レビューを実行する: まず仕様準拠レビュー、次にコード品質レビュー。

**核心原則:** タスクごとのフレッシュサブエージェント + 2段階レビュー（仕様→品質）= 高品質・高速イテレーション

**継続実行:** タスク間でユーザーに確認を取らない。計画の全タスクを停止せず実行する。停止理由は: 解決不能な BLOCKED、進行を妨げる曖昧さ、全タスク完了のみ。

## 使用タイミング

- 独立タスクのある実装計画がある場合
- タスクが概ね独立している（分離して作業可能）
- 現セッション内に留まりたい場合

## プロセス

```
計画を読む → 全タスク抽出 → TODO リスト作成
    ↓
各タスクについて:
    ↓
実装サブエージェントをディスパッチ
    ↓
質問あり? → 回答して再ディスパッチ
    ↓
実装・テスト・コミット・セルフレビュー
    ↓
仕様レビューサブエージェントをディスパッチ
    ↓
仕様準拠? → No → 修正 → 再レビュー
    ↓ Yes
品質レビューサブエージェントをディスパッチ
    ↓
品質承認? → No → 修正 → 再レビュー
    ↓ Yes
タスク完了 → 次のタスク
```

## モデル選択

各役割を処理できる最も軽量なモデルを使用する。

- 機械的実装タスク（1-2ファイル、明確な仕様）→ 高速・安価モデル
- 統合・判断タスク（複数ファイル調整）→ 標準モデル
- 設計・レビュータスク → 最高性能モデル

## 実装者ステータスの処理

- **DONE:** 仕様準拠レビューに進む
- **DONE_WITH_CONCERNS:** 懸念事項を読み、対処判断
- **NEEDS_CONTEXT:** 不足コンテキストを提供して再ディスパッチ
- **BLOCKED:** ブロッカーを評価し、適切に対応
