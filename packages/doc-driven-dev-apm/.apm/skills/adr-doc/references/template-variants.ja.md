# ADR テンプレートバリアント

このリファレンスは、`adr-doc` skill に同梱されている MADR 4.0.0
テンプレートの選択基準を定義します。

## 既定

既定では `full` を使います。作成者が明示的に軽量なテンプレートを選ばない限り、
構造化された判断過程、decision drivers、トレードオフを残すためです。

`minimal` は、判断が単純で、誤解が起きにくく、保存すべき重要なトレードオフが
少ない場合に限って選びます。迷う場合は `full` を選びます。

## バリアント概要

| テンプレート | 使う場面 |
| --- | --- |
| `minimal` | 判断が単純で、低リスクで、誤解されにくく、トレードオフが最小限の場合。 |
| `full` | 構造化された判断過程、明示的なトレードオフ、または選択肢間の比較を残す必要がある場合。 |
| `bare-minimal` | 既存リポジトリの規約が ADR 文言を定義済みで、MADR の最小セクション構造だけを挿入したい場合。 |
| `bare` | 既存リポジトリの規約が ADR 文言を定義済みで、MADR の完全なセクション構造が有用な場合。 |

## `full` を選ぶ場合

次のいずれかに当てはまる場合は `full` を選びます。

- 複数の実質的な選択肢があり、構造化されたトレードオフを ADR に残したい。
- decision drivers を明示する必要があり、どの判断基準が重要だったかを残したい。
- 後から判断を見直す可能性があり、選択肢間の比較を残す必要がある。
- ステークホルダーが結論だけでなく判断過程を見る必要がある。
- 判断の影響が大きい、複数チームにまたがる、リスクが高い、
  コンプライアンスに関わる、または運用上戻しにくい。

将来の読者が、現実的な代替案と比べてなぜ選択案がよかったのかを理解する
必要がある判断では `full` を使います。

## `minimal` を選ぶ場合

次のすべてに当てはまる場合に限って `minimal` を選びます。

- 判断が単純で局所的である。
- 実装方針が誤解されにくい。
- トレードオフが明白、または最小限である。
- 背景、検討した選択肢、結論を残せば将来の読者に十分伝わる。
- ステークホルダーが詳細な代替案比較を必要としていない。

単に ADR を短くしたいという理由だけで `minimal` を使わないでください。
実質的な代替案や自明でない判断基準がある場合は `full` を使います。

## `bare` または `bare-minimal` を選ぶ場合

bare テンプレートは、既存リポジトリの規約が説明文を既に定義しており、
この skill がテンプレート内の補助説明を追加しない方がよい場合に限って
選びます。

- `bare-minimal` は、MADR の最小セクション構造だけが必要な場合に使う。
- `bare` は、MADR の完全なセクション構造は有用だが、説明文は不要な場合に使う。

不確実性を隠す、トレードオフ分析を省く、複雑な ADR を単純に見せる、
といった目的で bare テンプレートを選ばないでください。
