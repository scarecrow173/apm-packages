# briefing-profile Schema

This document defines the structure and validation rules for the
`briefing-profile.md` file generated by `briefing-flow`.

## File Location

- **Path:** Repository root `briefing-profile.md`
- **Generated by:** `briefing-flow` skill (on first run)
- **Updated by:** `briefing-flow` (when staleness is detected)

## YAML Front Matter (Required)

```yaml
---
type: briefing-profile
version: "1.0"
generated: "YYYY-MM-DD"
last_validated: "YYYY-MM-DD"
repository: "<repository-name>"
---
```

| Field | Type | Required | Description |
| ----- | ---- | -------- | ----------- |
| type | string | yes | Must be `briefing-profile` |
| version | string | yes | Schema version (semver) |
| generated | string | yes | ISO date when profile was first generated |
| last_validated | string | yes | ISO date when profile was last validated against available skills |
| repository | string | yes | Repository name for identification |

## Sections

### 1. Available Skills

Table listing all discovered skills with metadata.

| Column | Required | Description |
| ------ | -------- | ----------- |
| Name | yes | Skill identifier (matches directory/file name) |
| Category | yes | One of the defined Briefing categories |
| Source | yes | Where the skill was discovered |
| Activation | yes | One of `always-on`, `conditional`, `excluded` |
| Execution | yes | One of `rigid`, `flexible` |
| Condition | no | If Activation is `conditional`, describe the trigger |

### 2. Category Assignments

Groups skills by category. Each category has a description and list of assigned skills.

**Valid categories:**

| Category | Purpose | Examples |
| -------- | ------- | -------- |
| Frame | Structures problems and options | idea-refine, brainstorming, interview-me |
| Discover | Explores and finds information | steer-web-research, external info gathering |
| Research | Conducts deep-dive investigation | source-driven-development, doc verification |
| Validate | Verifies accuracy and completeness | doubt-driven-development, adversarial analysis |
| Document | Produces formal documents | spec-doc, adr-doc |
| Meta | Orchestrates other skills | briefing-flow, doc-driven-dev-flow |

### 3. Default Stack

Defines the base skill combination applied to standard briefings.
This is the "starting point" that gets augmented based on Entry Decision.

Structure:

```markdown
## Default Stack

| Priority | Category | Skill | Rationale |
| -------- | -------- | ----- | --------- |
| 1 | Document | spec-doc | Every briefing produces a specification |
| 2 | Document | adr-doc | Every briefing produces an ADR |
```

### 4. Override Rules

Section for routing overrides based on Entry Decision and information state.

Structure:

```markdown
## Override Rules

| Condition | Action | Reason |
| --------- | ------ | ------ |
| Entry Decision = A-1 | Activate all Frame-category skills | Problem definition is ambiguous |
| Entry Decision = A-2 | Activate Frame-category (comparison) | Trade-off analysis needed |
| Entry Decision = A-5 | Activate Discover + Research | External research needed |
| External API/library involved | Activate Discover + Research | Primary source reference needed |
| Multiple approaches exist | Activate Frame + Validate | Option structuring and verification needed |
| Unprecedented architecture decision | Activate Research + Validate | Evidence gathering and assumption verification |
```

### 5. Information State Indicators

Indicators that assist Entry Decision. Used during Phase A assessment.

Structure:

```markdown
## Information State Indicators

| Indicator | Description | Suggests |
| --------- | ----------- | -------- |
| Problem clarity | Can the problem be explained in one sentence? | Low → A-1, High → A-4 |
| Direction clarity | Is there a solution direction? | Partial → A-2 |
| External dependency | Is external information needed? | Yes → A-5 |
| Convergence need | Do multiple sources need convergence? | Yes → A-3 |
```

## Validation Rules

1. All skills in "Available Skills" must have a valid category from the defined set.
2. All skills in "Default Stack" must exist in "Available Skills".
3. `activation` must be one of `always-on`, `conditional`, `excluded`.
4. `conditional` skills must have a non-empty `Condition` field.
5. "Document" category must have at least one `always-on` skill (spec-doc or adr-doc).
6. "Meta" category must not appear in the Default Stack (meta skills orchestrate, they don't execute).

## Staleness Detection

The profile is considered stale if:

1. A new skill directory exists that is not listed in "Available Skills".
2. A listed skill's source directory no longer exists.
3. `last_validated` is more than 30 days ago.
4. New information-gathering skills have been installed.

When staleness is detected, `briefing-flow` proposes an update rather than silently regenerating.
