# 多層防御（Defense in Depth）

根本原因の発見・修正後に、複数レイヤーでバリデーションを追加する。

## 目的

根本原因を修正した後、類似の問題がユーザーに到達することを防ぐ防御的チェックを複数レイヤーに追加する。

## パターン

```
Layer 1: 入力バリデーション（不正データを早期に検出）
    ↓
Layer 2: ビジネスロジックアサーション（不正状態を検出）
    ↓
Layer 3: 出力バリデーション（不正レスポンスを検出）
    ↓
Layer 4: モニタリング/アラート（本番での問題を検出）
```

## 適用タイミング

根本原因を修正した後に問う:
- 類似の不正値が再びこの地点に到達しうるか？
- 修正が誤って revert されたらどうなるか？
- 別の呼び出し元が類似の不正データを送ったらどうなるか？

## キールール

- 多層防御は根本原因修正の代替ではない
- 修正の後に適用する（代わりにではなく）
- 各レイヤーは独立であるべき
- 過度にバリデートしない — バグが越えた境界に集中する
