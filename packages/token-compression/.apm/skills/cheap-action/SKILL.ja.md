# Cheap Action

このスキルは、少ない推論で機械的に完了・検証できる、単純で境界のはっきりした作業に使う。

## 目的

低リスク作業のモデルコストを下げる。現在のハーネスが、必要なツールを使えるより低コストなモデルや低コストな委譲経路を提供しているなら、その選択肢に切り替えて境界のある作業だけを実行する。ハーネスにモデル選択がない場合は、現在のモデルのまま作業を小さく保ち、機械的に進める。

このスキルは助言的な契約として扱う。ハーネスが実際に切り替えを提供し、確認できた場合を除き、モデル切り替えが行われたと主張しない。

## cheap-action の対象

最も低コストな利用可能モデルを使ってよい作業:

- 名前付きコマンドやスクリプトの実行と結果報告。
- スコープが明確で検出可能な、変数名・関数名・ファイル名・import・include の機械的な rename。
- 既存のローカルなパターンに合わせた単純な import / include 解決。
- 直近の使用パターンから推論できる単純な型注釈。
- 関数シグネチャや近接する動作から導けるコメント更新。
- YAML、JSON、TOML、INI などの構造化設定ファイルの軽微な編集。
- status 確認、diff 要約、staging、commit、branch 確認などの routine な Git 操作。
- grep 風の検索とファイル一覧取得。
- 明確な parser / compiler / linter エラーに対する構文レベルの修正。
- 機械的な import 更新を伴うファイル移動・コピー。

## cheap-action を使わない場合

次の作業では current/default の reasoning model を使う:

- アーキテクチャ、プロダクト、セキュリティ、法務、医療、財務、ポリシー判断が必要な場合。
- 多数のファイルや自然言語要件をまたいだ曖昧な意図の推定が必要な場合。
- 作業範囲を決める前に広いコード理解が必要な場合。
- 破壊的操作、権限変更、秘密情報の扱い、公開、デプロイ、外部への副作用がある場合。
- plan、design、code review、threat model、root-cause analysis が必要な場合。
- 実行前に決定的な検証手順を名前付きで示せない場合。

## ルーティング手順

実行前に次を確認する:

1. 境界のある作業を言語化する。
2. 機械的な検証手順を言語化する。
3. その作業が cheap-eligible か判断する。
4. cheap-eligible で、かつハーネスがより低コストな利用可能モデルを提供するなら、そちらへ切り替えるか委譲する。
5. より低コストな利用可能モデルがない場合は、切り替えたふりをせず現在のモデルのまま続ける。
6. 境界のある作業だけを実行する。
7. 結果を機械的に検証する。
8. 検証に失敗したり、範囲が広がったり、曖昧さが出たら current/default の reasoning model に戻す。

## 伝え方

ユーザー向けの文は短くする。 routine な作業なら 1 文でよい:

`Cheap action: 既存スクリプトを実行して結果を報告する。`

モデル経済の説明は求められたときだけ行う。利用できないモデル切り替えについては言及しない。

## 出力

報告する内容:

- どの境界のある作業を実行したか。
- 検証が通ったか。
- ユーザーが必要とする正確な出力やファイルパス。
- cheap routing から外れた理由があるなら、その理由。
